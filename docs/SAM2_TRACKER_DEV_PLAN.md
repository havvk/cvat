# 开发计划：实现无服务器版 SAM2 视频追踪功能

## 1. 目标

创建一个全新的 CVAT 无服务器 (Serverless) 函数，将 SAM2 模型的视频目标追踪 (Video Tracking) 能力，以“追踪器 (Tracker)”的形式集成到 CVAT 的 AI 工具中。用户在视频标注任务中，可以通过在第一帧选择一个物体，然后在后续帧中自动追踪该物体的掩码 (mask)。

## 2. 核心技术与思路

- **核心模型**: 利用 `sam-2` Python 库中现成的 `SAM2VideoPredictor` 类，该类封装了视频追踪的完整算法。
- **集成方式**: 创建一个 `type: tracker` 类型的 Nuclio 函数。这需要我们的函数遵循 CVAT 为追踪器类型定义的特定API约定。
- **基本流程**: 用户在 UI 上点击“Track”后，前端会向我们的函数发送一个“初始化”请求；用户切换到下一帧时，前端会发送“追踪”请求。

## 3. 关键挑战：状态管理

与“交互器”不同，“追踪器”是**有状态的**。模型必须记住它在上一帧追踪的物体特征（在 SAM2 中被称为“记忆嵌入 (memory embedding)”），才能在下一帧中继续追踪。而无服务器函数天然是无状态的，每次请求都是独立的。因此，如何在多次请求之间维护和传递这个“追踪状态”是最大的挑战。

### 状态管理方案对比

1.  **方案A：客户端持有状态 (推荐)**
    -   **流程**: 后端在完成每一步（初始化或追踪）后，将更新后的“追踪状态”数据返回给前端。前端在发起下一次请求时，再将这个状态数据传回给后端。
    -   **优点**: 后端完全无状态，易于实现和扩展。这与我们已经部署的 SAM2 交互器（它将17MB的特征图返回给前端）的工作模式类似。
    -   **缺点**: 如果“追踪状态”数据过大，在网络间来回传递会产生一定的延迟。

2.  **方案B：服务器端缓存状态 (Redis)**
    -   **流程**: 后端将“追踪状态”存入一个外部的、共享的缓存数据库中（例如 CVAT 已内置的 Redis），只返回给前端一个追踪ID。下次请求时，前端只传递ID，后端根据ID从Redis中取出状态。
    -   **优点**: 网络传输的数据量极小，速度快。
    -   **缺点**: 增加了后端的复杂度，需要管理缓存的创建、读取和过期。

### 推荐方案

我们应首先采用**方案A (客户端持有状态)**。这是最简单、最符合 Serverless 思想的实现方式。我们可以先将功能打通，如果未来发现性能瓶颈，再考虑优化为方案B。

## 4. 函数 API 设计

我们的 Serverless 函数需要能处理两种不同类型的请求：

- **初始化请求 (`init`)**: 当用户在第一帧选定物体时触发。
    -   **输入**: 包含 `image` (图像) 和 `mask` (用户指定的初始掩码)。
    -   **处理**: 调用 `SAM2VideoPredictor` 的初始化方法，生成一个初始的“追踪状态”。
    -   **输出**: 将序列化后的“追踪状态”对象（Base64编码）作为 JSON 返回。

- **追踪请求 (`track`)**:
    -   **输入**: 包含 `image` (新一帧的图像) 和 `state` (上一步返回的“追踪状态”对象)。
    -   **处理**: 反序列化 `state`，恢复追踪器，调用 `track_step` 方法处理新图像，计算出新的掩码。
    -   **输出**: 返回包含 `mask` (新的分割掩码) 和 `state` (更新后的“追踪状态”) 的 JSON 对象。

## 5. 实施步骤

1.  **创建目录**: 在 `serverless/` 目录下，创建一个新文件夹 `custom_sam2_tracker` 用于存放我们的新功能代码。
2.  **编写 `function.yaml`**: 创建 Nuclio 配置文件。最关键的是在 `metadata.annotations` 中，将 `type` 设置为 `tracker`。
3.  **编写 `model_handler.py`**: 创建一个 Python 类，封装 `SAM2VideoPredictor`。这个类需要包含 `init_tracker` 和 `track_next_frame` 等核心方法，并处理状态的序列化/反序列化。
4.  **编写 `main.py`**: 编写主 `handler` 函数。它负责解析收到的请求，判断是 `init` 还是 `track` 请求，然后调用 `model_handler` 中相应的方法。
5.  **部署与调试**: 编写完成后，使用 `deploy_gpu.sh` 脚本进行部署，并在 CVAT 界面中进行端到端的测试和调试。
